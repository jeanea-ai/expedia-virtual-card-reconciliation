# v0.2.2 extractor regression plan

## Source

A manual read-only Expedia Partner Central reconciliation on 2026-09-21 completed safely but returned `incomplete` and did not generate a certified PDF. The property, guest, reservation, authorization, and run identifiers are intentionally omitted from this document.

## Confirmed defects

1. **Deactivated-card balance badge**
   - Observed: a deactivated card renders `Deactivated` in the remaining-balance column instead of a monetary value.
   - Required behavior: preserve `cardStatus: "Deactivated"`, set the remaining balance to `null`, and do not treat the badge as malformed currency.
   - Safety: a deactivated card must never enter the ready-to-charge queue or contribute to a chargeable total.

2. **Empty refund queue without a table**
   - Observed: the refund section renders a heading and an explicit empty-state message but no table.
   - Required behavior: recognize the known empty-state message as a valid empty refund queue.
   - Safety: absence of both a recognized table and a recognized empty-state message must remain fail-closed.

3. **`Check-in date` header alias**
   - Observed: Expedia uses `Check-in date`, which is not currently recognized.
   - Required behavior: map `Check-in date` to the normalized check-in field.

4. **Displayed-range noise**
   - Observed: the displayed-range matcher captured unrelated page text resembling `761-2 of 2`.
   - Required behavior: scope range parsing to the queue pagination control and accept only a valid range whose start is less than or equal to its end.

## Regression coverage required before release

- Add sanitized HTML/JSON fixtures reproducing all four states without real guest, reservation, property, card, or run data.
- Add extractor tests for each defect and at least one combined-page test.
- Confirm a page containing only deactivated cards produces zero actionable charge/refund items without certifying a monetary balance that was not displayed.
- Confirm a recognized empty refund message produces an empty queue rather than `section_not_found`.
- Confirm an unrecognized missing refund section still fails closed.
- Confirm `Check-in date` is extracted.
- Confirm unrelated numeric text cannot become the displayed range.
- Run the complete test suite and require all tests to pass.
- Perform a manual read-only Kolo test before publishing v0.2.2.

## Release boundary

This plan authorizes tracking and implementation only. Publishing v0.2.2 requires a separate explicit approval after review, tests, and the manual read-only validation.
